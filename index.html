Exhibit 01

Housing data collector

  • Python
  • Scraping
  • Validation
  • CSV / SQL

A scheduled collector that pulls rental listings, normalises prices and addresses, removes duplicates and rejects malformed rows before they reach the analysis table.

Source on GitHub →

14,862 clean listings collected in nine weeks 97.2% of scraped rows passed validation; 2.8% were rejected as duplicates or malformed.

Finding: volume peaked in week 7, when the collector added a second source. The validation rate stayed above 96% every week.

Exhibit 02

FitTrack

  • JavaScript
  • Local storage
  • Charts

A workout tracker that records sets, reps and load, then estimates one-rep maxes so you can see progress as a trend instead of a list of sessions.

Source on GitHub →

+18% estimated squat 1RM over an 8-week block Epley estimate from logged sets, 100 kg → 118 kg.

Finding: the trend line exposed a plateau in weeks 4–5. A deload in week 5 was followed by the three largest gains of the block.

Exhibit 03

Statistical analysis in R

  • R
  • tidyverse
  • lm()
  • ggplot2

An end-to-end study: exploratory analysis, a linear model, residual diagnostics and a write-up that states what the model can and can't support.

Source on GitHub →

0.92 R² of the fitted model, p < 0.001 Ordinary least squares on 24 observations. Residuals checked for normality and constant variance.

Finding: each extra unit of the predictor is associated with a 1.5-point increase in the outcome. The relationship holds across the full observed range.

Exhibit 04

Task breakdown tool

  • JavaScript
  • Estimation
  • UX

You type in a vague goal and get back a sequence of concrete steps, each with a time estimate, so the size of the work is visible before you start.

Source on GitHub →

1 → 7 one goal broken into seven timed steps Example run: “Publish a portfolio”, 3 h 05 min in total. No step is longer than 45 minutes.

Finding: writing the project copy is the longest step (45 min), so it should be scheduled first rather than left until the end.
